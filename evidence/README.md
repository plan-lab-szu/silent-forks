# Evidence Index

These files retain observations that depend on a specific CPU architecture,
compiler target, build tag, or consensus-client configuration. Portable checks
are regenerated by `artifact/run_quick.py`; this directory is for results that
cannot be reproduced faithfully on every evaluator's machine.

| File | Supports |
|---|---|
| `float_divergence_linux_amd64_ci.log` | Six Go floating-point strategies produce five commitments on native Linux `amd64` |
| `float_divergence_linux_arm64_ci.log` | The same strategies produce six commitments on native Linux `arm64` because the fused path contracts |
| `minimal_counterexample_linux_*.log` | Compact witnesses on the two native CI architectures |
| `minimal_counterexample_*_native.log` / `*_emulated.log` | Independent Windows-on-ARM reproduction of the compact witnesses |
| `fma_codegen_by_target.txt` | Target-specific FMA instruction selection in Go code generation |
| `attacker_closure.log` | One-client changes split six implementations on real MNIST coordinates |
| `differential_conformance.log` | Nine curated and 2,000 randomized Go/Python cases, including mutation sensitivity |
| `mandatory_aggregation.log` | Empty-transaction boundary scheduling and propagation into the post-state root |
| `mandatory_aggregation_divergence.log` | Two same-architecture binaries with different accumulation orders commit different boundary roots |
| `engine_invalid_payload.log` | `engine_newPayload` returns `INVALID` for the divergent root over an identical parent |
| `e3lite_arm64_vs_amd64.log` | Linux `arm64`/`amd64` geth processes commit different results for the vulnerable floating-point path |
| `e3lite_native_windows_rerun.log` | The same architecture-dependent result on a second OS/runtime substrate |

Every log begins with its producing command or environment when that
information is required for interpretation. Logs demonstrate the recorded run;
the source tests and fixed inputs remain the authoritative reproduction path.
